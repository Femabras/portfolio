Highlights

    Real-time online chess

    Send a friend an invite link and play in the browser. Server-Sent Events push every state change to both players and to anyone watching, and a server-side engine is the single source of truth: the client sends only the move itself, and the server validates it, applies it and broadcasts the new position. Your own move appears at once and rolls back if the server rejects it.

    A predictions engine that answers to its backtest

    A Poisson score model in Go, using team strengths for leagues and Elo ratings for tournaments, prices results, goal totals and both-teams-to-score. A backtest grades past picks with the production code. League multi-leg picks hit 39–45% against 55–67% predicted, so they were switched off; tournament picks hit 59.8% against 56.7% and stayed.

    A map without a maps bill

    The ATM finder draws with MapLibre GL from a self-hosted, Angola-only vector map: a 210 MB PMTiles archive on Cloudflare R2, read with HTTP range requests, so there is no commercial maps API to pay for or depend on.     Sessions that don't drop

    Access tokens last 15 minutes. The Next.js proxy refreshes them before they expire and rotates the refresh token, with a 30-second grace window for requests already in flight. The client shares one refresh between concurrent calls and retries a rejected call once, but never on the auth endpoints or in the partner area, where sign-in locks out after repeated failures and a replay would count as a second one.

Debugging notes

The sign-in button that only failed on a first visit

Symptom
Google Sign-In failed for some visitors and worked for others. The production log showed both outcomes within the same hour.
What made it tricky
It always worked when you reached /login by clicking through the site. It failed only when /login or /register was the first page you loaded, which is exactly the path that testing from inside the app never takes.
Cause
The link came from a helper that picks the API origin by checking typeof window. That answers where the code is running, which is the right question for fetch and the wrong one for an href. On a server-rendered first load, the internal Docker hostname was written into the page, and no browser can reach it. The URL also lacked the /api prefix the OAuth client is registered with.
Fix
A separate public API origin for anything the browser resolves, used by both links. The 34 fetch call sites keep the dual-mode helper, which now carries a comment naming where it must never appear.

What I took from it: ask where a URL will be resolved, not where the code that builds it runs.

Process

How I work

The same habits on every change, whether it's a one-line fix or a new product area.

  1. Decide before building

    Each significant choice becomes an architecture decision record with the options, their tradeoffs and a recommendation, written before the code. Femabrás has more than 50.

  2. One gate, locally and in CI

    gofmt, go vet, Go tests and govulncheck, then the i18n check, frontend tests, lint and a production build, cheapest first so a failure shows up in seconds.

  3. Fix the cause

    A fix names the actual cause. If the real fix is out of scope, it gets written down rather than hidden behind a patch.

  4. AI-assisted, owned by me

    I write the spec and the ADR, Claude Code implements in plan mode, and I review every diff before it's committed. Documentation ships in the same commit as the change.

How Femabrás fits together

  1. Edge

    Cloudflare for DNS, proxy and TLS, with R2 holding images, map tiles and private media

  2. Web

    Caddy in front of Next.js 16 (App Router, server rendering, next-intl, session proxy), React 19, TypeScript and Tailwind CSS 4

  3. API

    Go with Gin: a REST API with JWT sessions, per-route rate limits and Server-Sent Events for live games, plus Asynq background jobs

  4. Data

    PostgreSQL through GORM, and Redis for queues, rate limits and short-lived state

  5. Delivery

    GitHub Actions to GHCR, then staging, then production on Hetzner with Docker Compose; restic backups to Backblaze B2
