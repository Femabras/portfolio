# Fernando Brás, portfolio

Personal portfolio and résumé, served by GitHub Pages at
<https://femabras.github.io/portfolio/>. Plain HTML, CSS and one small script,
with no framework and no request to any third party. The pages are written by
a small Node script from the files in `content/`, so every fact on them is
typed once.

## Layout

| Path | What it is |
| --- | --- |
| `content/site.mjs` | Facts every page shares: contact details, links, dates, counts, feature status, tags, the ticker, the terminal's steps |
| `content/en.mjs`, `content/pt.mjs` | The wording of each language (Portuguese in pre-1990 Angolan spelling) |
| `content/resume.mjs` | The wording of the résumé |
| `scripts/build.mjs` | Writes the generated pages below from `content/` |
| `index.html` | The English page (generated) |
| `public/portuguese-page.html` | The Portuguese page (generated) |
| `public/main.css` | The stylesheet both pages use; every colour is a token at its top |
| `public/main.js` | Theme toggle, scroll reveals, count-up stats, card spotlight, active-section marker, the hero terminal, the footer year |
| `resume/resume.html` | The source of the résumé PDF (generated) |
| `resume/resume.css`, `resume/fonts/` | The résumé's styles and its static Inter weights |
| `social/og-card.html`, `social/og-card-pt.html` | The sources of the link-preview images (generated) |
| `assets/images/og-card.png`, `og-card-pt.png` | The link-preview images of the English and Portuguese pages |
| `assets/images/fernando-bras-portrait.webp` | The 400x400 head crop the pages show |
| `assets/images/` (rest) | Studio photo and favicon |
| `assets/fonts/` | Inter and JetBrains Mono, self-hosted (SIL Open Font License, texts alongside) |
| `assets/pdf/fernando-bras-resume.pdf` | The résumé the pages link to |

## Change something

1. Edit the file that holds it:
   - a fact (email, phone, a date, a count, a feature going live, the stack,
     the terminal's steps): `content/site.mjs`
   - wording: `content/en.mjs` and `content/pt.mjs`, both of them
   - the résumé's wording: `content/resume.mjs`
   - a colour: the Tokens section at the top of `public/main.css`
2. Rebuild. Node 18 or newer, nothing to install:

   ```sh
   node scripts/build.mjs
   ```

3. Open `index.html` to check, then commit `content/` together with the pages
   it rewrote.

The build prints any step a change still needs by hand, such as printing the
résumé or capturing a preview card, and only when the page behind that step
changed. It refuses to run when a `{token}` is misspelt or when `en.mjs` and
`pt.mjs` do not have the same keys, so one language cannot silently fall
behind the other.

Generated pages start with a "Generated by scripts/build.mjs" comment. Do not
edit them by hand: the next build overwrites the edit. To confirm nothing was
edited or left unbuilt:

```sh
node scripts/build.mjs --check
```

It exits 1 and names the stale pages. The footer year is written at build
time and corrected in the browser by `public/main.js`, so a page that nobody
rebuilds still shows the right year; `--check` does report the pages as stale
after New Year until the next build.

## Preview

Open `index.html` in a browser. Everything works from disk, offline.

```sh
xdg-open index.html
```

The page follows the system's light or dark setting until the visitor uses the
sun and moon button in the header; the choice is remembered in the browser
(`localStorage`, key `theme`).

## Publish

Push to `main`; GitHub Pages publishes the files as committed. It does not run
the build, so build before committing.

## Change the portrait

The pages show a square crop, not the original photo: a portrait photo shown
in a circle is cut to its middle square, which cuts off the top of the head.
For a new photo, crop a square that starts just above the hair, 400 by 400
pixels, saved as `assets/images/fernando-bras-portrait.webp`. With
ImageMagick, where `photo.png` is the new photo (keep the original outside
the repository; the site only needs the crop):

```sh
convert photo.png -resize '400x400^' -gravity north -extent 400x400 -quality 84 assets/images/fernando-bras-portrait.webp
```

`-gravity north` keeps the top of the photo, so the head stays whole. On
ImageMagick 7 the command is `magick` instead of `convert`.

Then rebuild: the pages take the image's width and height from the file.

## Update the résumé

1. Edit `content/resume.mjs` (or a fact in `content/site.mjs`) and rebuild.
2. Open `resume/resume.html` in Chrome or Chromium and print (Ctrl+P).
3. Destination: Save as PDF. Paper size: Letter. Margins: Default. Tick
   Background graphics. The page size and margins come from the file itself.
4. Save over `assets/pdf/fernando-bras-resume.pdf`.

It is one US Letter page because it targets US roles. For A4, change
`size: Letter` in the `@page` rule of `resume/resume.css` and the `.page`
width and height to 210mm by 297mm. Check the preview is still one page after
any edit: the page box hides overflow rather than spilling onto a second page.

The résumé uses static font weights, not the variable font the site uses:
Chromium writes a variable font into a PDF as Type 3 glyphs, which some
applicant-tracking systems parse badly. Section headings avoid letter-spacing
for the same reason.

## Update the link previews

When a page's link is shared on LinkedIn, WhatsApp, Slack or email, the app
shows a preview image named in that page's `og:image` tag: `og-card.png` for
the English page, `og-card-pt.png` for the Portuguese one. They carry the
name, role, location, tagline and stack as pixels, so they need capturing
again when one of those changes:

1. Rebuild, so `social/og-card.html` and `social/og-card-pt.html` are current.
2. Open `social/og-card.html` in Chrome or Chromium and press F12.
3. In the Elements panel, right-click the `<body>` line and choose
   "Capture node screenshot".
4. Save it over `assets/images/og-card.png`.
5. Repeat with `social/og-card-pt.html` and `assets/images/og-card-pt.png`.
6. Rebuild once more: the pages take each image's size from the file.

On a screen with display scaling the capture comes out larger than 1200 by
630, which preview images accept. Apps keep old previews for days; LinkedIn's
Post Inspector (<https://www.linkedin.com/post-inspector/>) fetches a fresh
one.

## Rules this site keeps

- No external requests. Fonts, icons and the script are local; nothing loads
  from a CDN. Icons are one inline SVG sprite per page, because an external
  sprite file does not load when the page is opened straight from disk.
- No pure black or pure white, not even the `transparent` keyword (it is
  `rgba(0, 0, 0, 0)`). The palette is `#001514` ink on `#fbfffe` paper, with
  `#04706b`, `#2aba8a`, `#7ed3be` and `#e0b25a` in the gradients.
- Every colour is set once, in the Tokens section of `public/main.css`; the
  rules below it only use `var()`. The dark theme's values are the `--dark-*`
  tokens, and the two dark blocks after them list names, never values.
- Every text colour passes WCAG AA contrast in both themes, including over the
  hero's tinted background. Gradient text is only used at large sizes.
- Motion is decoration: scroll reveals, the drifting hero background, the
  rotating portrait ring, the ticker, the looping terminal and the chess pawn.
  All of it stops under `prefers-reduced-motion`, and the terminal only runs
  while it is on screen.
- Nothing depends on the script. The hero's entrance is CSS; content below the
  fold is hidden only by `public/main.js` itself, just before it reveals it;
  the stats and the footer year carry real values in the HTML; the theme
  button stays hidden without JavaScript.
- The English and Portuguese pages carry the same sections in the same order.
  The build enforces it.

## Going back to hand-written HTML

The generated pages are ordinary static HTML. To stop using the build, delete
`content/` and `scripts/`, remove the "Generated" comment from the top of each
page, and edit the HTML directly from then on.
